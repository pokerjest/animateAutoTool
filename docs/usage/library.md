# 本地媒体库与整理

## 添加媒体目录

在“本地媒体”中添加下载根目录或现有媒体目录。应用会：

1. 递归发现视频、字幕、NFO 和图片；
2. 先读取目录结构和 sidecar，再运行确定性文件名解析；
3. 使用已有数据库记录、文件指纹和 provider ID 恢复关联；
4. 联查 Bangumi、TMDB 和 AniList 的真实候选；
5. 生成带证据和冲突提示的整理预览；
6. 在确认后移动、重命名或补充 NFO 与图片。

## 推荐目录结构

```text
媒体根目录/
└── 系列名/
    ├── Season 01/
    │   ├── 系列名 - S01E01.mkv
    │   └── 系列名 - S01E01.zh-Hans.ass
    └── Season 02/
```

同一作品的不同季度会归入同一个系列目录；不同年份的重制版会尽量保持独立。

## 识别规则

确定性解析器支持：

- `S01E01`、`S01 E01`、`1x01`；
- `Season 01`、`第 1 季` 和中文集数；
- 绝对集数和 `01-02` 多集范围；
- SP、OVA、OP、ED、预告等特殊类型；
- 常见中英文、日文标题和括号格式。

年份、分辨率、编码、语言、发布组和 V2/V3 会作为技术标签提取，避免误识别成集数。多集合集或特殊条目无法安全映射到普通整数集数时，应用会标记冲突并给出人工处理建议，不会强行写入错误集号。

## 增量扫描与数据安全

扫描器会记录路径、文件大小、修改时间和内容指纹。增量扫描只处理新增、删除或指纹变化的文件；下载完成后则优先扫描受影响的番剧目录。

- 多个扫描根目录会规范化并去除嵌套重复；
- symlink、权限错误和不可访问路径会记录为扫描问题；
- 扫描不完整时禁止批量清理数据库，避免把暂时离线的媒体盘当成已删除；
- 文件移动或目录改名后，会用指纹、provider ID 和历史路径尝试恢复原记录；
- 扫描只更新索引，不会删除实际媒体文件。

本地番剧列表使用分页和自动加载。网络或磁盘较慢时，前端会等待当前请求完成，不会把一次延迟当作“已经没有更多数据”。

## NFO、字幕与图片

应用会把相同 stem、版本和集数的视频、字幕、NFO 与图片关联。兼容的 sidecar 包括：

```text
tvshow.nfo
{episode}.nfo
poster
fanart
backdrop
banner
clearlogo
landscape
folder
```

生成 NFO 和图片时使用临时文件、校验和原子替换，写入中断不会留下半成品。默认按字段分层合并：本地 NFO 和人工锁定字段优先，网络来源只补充缺失内容；只有明确选择覆盖策略时才替换已有字段。

## 三源匹配与 AI 协助

Bangumi、TMDB 和 AniList 会并行搜索，并可根据一个来源的标题、年份和别名补查另外两个来源。匹配只接受服务真实返回的候选 ID；每个字段会记录来源和更新时间。

确定性解析失败、NFO 与数据库冲突或多个真实候选无法区分时，页面可以发起“AI 协助识别”。AI 只能排序候选、解释证据并生成提案，不能虚构外部 ID、指定任意目标路径或直接修改文件。最终仍需在业务页面预览并确认。

## 整理前检查

- 预览中的源文件仍然存在；
- 目标目录没有同名文件；
- qBittorrent 正在做种的文件没有被外部程序占用；
- 路径位于应用和下载器都能看到的文件系统中；
- 预览生成后文件大小、修改时间和指纹没有发生变化；
- 不确定时先整理一部小作品，不要一次处理整个媒体盘。
