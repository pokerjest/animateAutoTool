# 备份、恢复与诊断

## 加密备份

当前备份页创建完整备份，包含数据库、设置、订阅、元数据、用户数据和本地媒体索引。所有新备份在导出到本地或上传 R2 前都会：

1. 生成一致的 SQLite 备份；
2. 压缩为 ZIP；
3. 使用 AES-256 加密数据库和 manifest；
4. 记录格式版本、应用版本、schema、大小和 SHA256。

默认归档密码是用户在对话框中再次输入并通过验证的当前管理员密码，也可以使用至少 8 位的独立密码。密码不会保存，忘记后无法恢复。

完整备份可能包含已经保存的 API Key、Token 和服务密码，因此即使文件已加密，也不应公开分享。旧版原始 `.db` / `.sqlite` 备份以及选择性备份仍可读取；选择性恢复会保留当前设备已有的敏感配置，不会用缺失或空白字段清除凭据。

恢复前先使用“分析备份”输入对应密码，确认格式、校验结果和可恢复分类。执行恢复前应用会创建当前数据库与配置快照；写入或配置同步失败时使用该快照恢复，避免数据库和 `config.yaml` 状态分裂。

恢复是按分类执行的。缺少某张表时不会删除当前对应表；写入前会校验用户、番剧、episode、metadata 和 playback history 的依赖，恢复本地库后会重新修复番剧 identity、索引和统计。恢复用户表后，现有登录会话会立即失效，必须重新登录。

恢复完成后应用会执行 SQLite 完整性/快速检查、schema 版本校验、孤儿引用检查和关键表计数校验。若配置镜像导出失败或数据库校验失败，优先从“恢复前快照”回退，不要在同一份数据库上重复尝试破坏性操作。

## 健康检查

“系统健康”页面会检查：

- qBittorrent、Jellyfin、R2、元数据和 AI 等已启用服务是否已配置；
- `server.public_url` 是否为 HTTPS；
- `trusted_proxies` 是否过于宽泛；
- 运行时 goroutine、堆内存、GC 和运行时长；
- 订阅是否长时间未更新；
- 媒体库是否存在未匹配或缺失文件。

## 诊断包

导出的诊断包应优先提交给维护者，而不是直接发到公开 Issue。导出前仍需人工检查压缩包内的服务地址、错误详情和路径。

诊断包会对密码、Token、API Key、Cookie 和认证头脱敏，但会保留定位问题所需的媒体路径、任务状态和错误摘要。

## 更新与回切

设置页的维护更新支持稳定版和测试版通道。一个版本是否显示为“可安全切换”，取决于 Release 兼容清单、当前数据库 schema、平台安装包和 SHA256 校验，而不只是版本号大小。

更新前会保存数据库和配置快照。新版本启动后必须通过仅限本机的 readiness 检查；启动失败、迁移未完成或数据库不可读时，更新辅助进程会恢复旧二进制、数据库和配置。自动更新只向前升级；测试版切回稳定版必须由目标 Release 的兼容清单明确允许。

详见[版本通道、更新与回切](updater.md)。
